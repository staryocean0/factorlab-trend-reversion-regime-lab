## Source assessment

### 1. CFFEX official historical data service — preferred

CFFEX states that its historical data products cover historical market data generated by listed products/contracts, including snapshot data, and provides four product families: Level-2, Level-1, one-minute and five-minute historical databases.

For this R1_B identity, the correct acquisition target is **official Level-2 historical snapshot data**, not the one-minute/five-minute OHLC database.

Official references:

- https://www.cffex.com.cn/lssjfw/
- https://www.cffex.com.cn/zlxz/
- https://www.cffex.com.cn/zz1000gzqq/

#### Official Level-2 field-capability confirmation — added 2026-09-10

CFFEX's own Level-2 market-information authorization guide describes the Level-2 product as five-level market data and explicitly includes:

- contract name / delivery month;
- latest price;
- volume;
- open interest;
- bid prices for the best five levels;
- ask prices for the best five levels;
- bid sizes for the best five levels;
- ask sizes for the best five levels;
- settlement/open/close/high/low/previous-settlement/turnover fields.

The same official guide states that Level-2 uses market **snapshot** sampling at **500 ms per sample** and notes that illiquid distant contracts may not emit a new snapshot if neither trades nor orders changed since the previous sample.

Official field-capability source:

- https://www.cffex.com.cn/u/cms/www/202201/20211342wucd.pdf

This is sufficient to confirm that the official CFFEX Level-2 product family has the top-of-book price/size capability required by the frozen canonical schema. It is **not** sufficient to admit a historical delivery by itself. The actual historical package still has to prove, from its delivered dictionary/sample before any R1_B event join:

- stable mapping of level-1 bid/ask and sizes;
- timestamp precision and exchange-local timezone semantics;
- historical snapshot generation rule/version;
- zero/missing quote encoding;
- trading-status / quote-validity semantics;
- contract-master / expiry reconstruction;
- correction/republication semantics.

Therefore the source status is upgraded only from an unverified capability assumption to:

`PREFERRED_SOURCE_FIELD_CAPABILITY_OFFICIALLY_CONFIRMED_DELIVERY_NOT_YET_ACQUIRED`

No historical MO quote rows have been inspected and no event-conditioned option outcome has been read.

### 2. AKShare / Sina MO interfaces — not admitted for historical primary execution

AKShare documents an MO board/spot interface exposing bid/ask-like fields for current/real-time snapshots, and a separate historical daily interface. That does not establish a provenance-stable historical intraday best-bid/best-ask tape for 2022-2025.

Status: `NOT_ADMISSIBLE_FOR_PRIMARY_HISTORICAL_EXECUTION_FROM_DOCUMENTED_INTERFACE`

### 3. Tushare `opt_mins` — not admitted for primary execution

Tushare documents historical option minute bars with fields such as open/close/high/low/volume/amount/open interest. The documented output does not include historical best bid, best ask, or quote sizes.

Minute OHLC can be useful for non-economic feasibility or inventory checks but cannot support the primary R1_B execution mapping because it suppresses executable spread.

Status: `NOT_ADMISSIBLE_FOR_PRIMARY_EXECUTION_FROM_DOCUMENTED_FIELDS`
