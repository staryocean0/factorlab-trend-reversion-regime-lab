## 现行文件结构

- `CONTINUE_HERE.md`：唯一接管入口。
- `docs/REPOSITORY_STATE.json`：机器状态、19模块生命周期、当前文档内容源及工作流注册。
- `docs/WHITEPAPER.md`：本仓当前研究与工程规范；不是上游白皮书或历史策略白皮书的替代认证。
- `docs/COMPONENTS.md`：模块、状态、解释报告和复现工作流对应关系。
- `docs/DATA.md`：数据身份、用途和未验证边界。
- `docs/TESTING.md`：快速门禁、完整测试及固定历史复现层级。
- `docs/research/README.md`、`docs/governance/README.md`：原位历史报告与冻结/裁决索引。
- `docs/archive/repository_pre_cleanup_20260912/`：39份清理前入口与配置的原字节副本；目录说明为ARCHIVE_INDEX.md，不覆盖原README。
- `scripts/repository_consistency.py`：生成与检查现行文档、组件依赖、工作流和保存边界。

所有历史白皮书都没有被冒充为当前白皮书。历史资料中当时的结论、路径和命令按原貌保存；当前目录索引明确说明它们不能作为新的执行授权。

## 删除、退役与保留

947个非清理对象的Git内容标识和文件模式与基线一致，其中包括所有原始data文件、冻结科学定义、决定性证据、原研究计算代码、旧测试及历史报告。39个需修改/迁移的原对象各有原字节归档。

物理移出当前活动路径的是旧seed清单和误导性的旧工作流入口；已完成提示词改为退役指示。一次性、带写权限的迁移工作流已从当前`.github/workflows`移除，迁移脚本仅作受限历史记录保留。

旧研究代码没有为了目录整齐而整体删除或改写：它们仍被原研究、测试或冻结复现引用，故采用保留依赖与取消默认执行相结合的退役方式。历史报告和证据采用原位归档，不破坏原路径和hash。文件总数因新增归档及维护检查而增加，不以减少总文件数冒充清理质量。

## 工作流与自动防失同步

当前共12个活动工作流：1个默认一致性入口、1个全套测试工作流、10个固定历史/来源复现工作流。全部只读仓库，checkout不保留凭据；历史复现不向Git提交新结果。

默认main推送/PR检查状态与裁决对应、37份生成文档、326条现行本地链接、19模块注册、全部现行Python语法及显式本地导入路径、测试文件登记、12个工作流的调用/权限/触发约束，以及基线保护。维护检查不是所有程序行为的形式化证明，也不检查所有历史快照内部链接是否仍在当前路径可运行。

完整验收通过`repository-consistency`的`full_regression`或受控提交标记`[full-regression]`显式开启，实际调用全部10个历史工作流和全套测试。历史预测拟合、模拟和计算仅对原冻结输入复现并对照原证据，不搜索新参数，不算新独立市场样本。

现行文档同步：

```bash
python scripts/repository_consistency.py --render
# 审阅并暂存预期改动后检查；不要把不相关本地修改一并提交。
python scripts/repository_consistency.py --check
```

环境启动：`bash .codex/cloud_setup.sh`。完整测试：`python -m pytest -q`，需具备测试说明列明的保留数据依赖。语义或研究状态变更仍必须有新的明确授权，并同步对应裁决及保护约束，不能仅改一句文案升级权限。

## 历史操作配置兼容处理

`research/etf_source_repair/verify_retained.py`原文件没有修改。其125个历史输入中，118个非操作性输入仍使用当前原文件，按原字节数、SHA256和Git对象标识精确核对；6个旧工作流和仅含文档字符串的`src/regime_lab/__init__.py`按原固定提交`ef18bf905e9e427153650d5538a996249bb6a901`提供到临时目录。

新增`scripts/verify_historical_source_impact.py`逐项报告这7个操作对象的当前/历史哈希，禁止把数据、公式、冻结规则或结果作为历史回退对象。init必须只有一条文档字符串，不能以此掩盖执行代码变化。临时目录内不执行历史工作流，不覆盖原仓文件，结束后校验原文件未变。原验证器的内部计数明确标注为临时兼容视图的计数，不混称125个当前文件全部未变。

## 验收结果

基线全套运行`34686075131`：492项测试，0失败、0错误、0跳过。

整理后全套运行`34687540076`，实现提交`dbb14b300c5e55d3a0a31917ce141f086924491c`：528项测试，0失败、0错误、0跳过。逐项比较测试标识，原492项全部仍在，新增36项维护及兼容边界测试，无删除旧测试。

受测提交的结构检查：1,048个跟踪文件；947个原对象未变；39个归档原副本；37份生成文档；326条当前本地链接；140份现行Python语法/显式导入路径；45个测试文件；19个研究模块；12个活动工作流。该计数不包含随后加入的本报告与验收摘要文件，后续CI会重新统计全树。

同一run的12个job均成功：快速一致性、全套测试，以及10条历史复现（字段对账、单日观察、上游说明、行动影响、可测量性、开发期噪声、关闭的对照设计、固定时间前推预测、旧价格/统计复现、无拟合证据收口）。原有容差、样本和决定性结果不因整理而放宽。

失败的中间维护尝试亦保留：归档README重名问题已修正；runner写工作流权限不足后，改由已授权GitHub connector发布已校验的精确配置；历史操作配置依赖在全量工作流运行中发现并按上述方式解决。它们不是科研结果失败，也没有通过删测试或改原结果掩盖。
